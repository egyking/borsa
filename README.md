# بورصة — مستشار أسهم وذهب السوق المصري 🇪🇬

تطبيق ويب يقدّم توصيات آلية (شراء / بيع / انتظار) لـ **24 سهماً** من البورصة
المصرية والذهب، على مستويين: **المضاربة (قصير الأجل)** و**الاستثمار (طويل الأجل)**
— مع أسباب كل توصية، مستوى المخاطرة، وقف الخسارة والهدف، وتأثير الأخبار العالمية.

> ⚠️ توصيات لأغراض تعليمية فقط وليست نصيحة استثمارية.

## الميزات

- **24 سهماً** عبر 7 قطاعات (بنوك، عقارات، اتصالات، صناعات، استهلاكية، رعاية صحية) + الذهب
- **أفضل الفرص**: ترتيب تلقائي لأقوى توصيات الشراء، مضاربة واستثمار
- **معنويات الأخبار العالمية**: تعديل محدود ومُفسَّر للتوصيات بناءً على أخبار اقتصاد
  مصر والذهب/الفائدة العالمية (عبر [GDELT](https://www.gdeltproject.org/) — مجاني، بلا مفتاح API)
- **اختبار تاريخي (Backtesting)**: تقييم walk-forward خارج العيّنة مع embargo
  يمنع تسرّب البيانات، مقاييس تصنيف + محاكاة تداول مقابل الشراء والاحتفاظ
- واجهة عربية RTL كاملة، عملة بالجنيه المصري

## المعمارية (Cache-First — مجانية وموثوقة)

```
GitHub Action (يومياً، مجاناً)
   └─ يدرّب النموذجين + يحسب التوصيات والأسعار والذهب
      └─ يكتب frontend/public/snapshot.json  ← الواجهة تقرأه مباشرة
```

لماذا؟ مصادر البيانات (Yahoo Finance و GDELT للأخبار) تفرض **حظر معدّل (rate limit)**
صارم على عناوين IP السحابية المشتركة (شوهد عملياً أثناء التطوير). بدل استدعائها عند
كل طلب (يفشل غالباً)، نحسب كل شيء **مرة واحدة يومياً** في GitHub Action (IP نظيف
في كل تشغيل) ونحفظ النتيجة في ملف ثابت تقرأه الواجهة فوراً — بلا حظر، بلا تكلفة،
وبلا حدود حجم على الخوادم.

## النماذج

- **نموذج المضاربة**: أفق 5 أيام، عتبة ±2.5%.
- **نموذج الاستثمار**: أفق 60 يوماً، عتبة ±10%.
- **19 مؤشراً فنياً**: RSI، MACD، المتوسطات (20/50/200)، بولينجر، ستوكاستيك، OBV، ATR، ROC…
- إن لم يوجد نموذج مدرّب، يرجع التطبيق تلقائياً لتوصيات قائمة على التحليل الفني (TA) فقط.
- **تعديل الأخبار**: نسبة شراء/بيع تُعدَّل ضمن حدود آمنة (±8 نقطة) بناءً على معنويات
  الأخبار، مع بقاء التحليل الفني هو المحرّك الأساسي للقرار دائماً.

## الاختبار التاريخي (Backtesting)

`backend/backtest.py` يقيّم النموذج بمنهجية **walk-forward** صارمة:
- نافذة تدريب متزايدة + `embargo` ≥ الأفق الزمني بين التدريب والاختبار (يمنع
  تسرّب التسميات المستقبلية `shift(-N)`)
- الـ `scaler` والنموذج يُعاد تدريبهما على بيانات الماضي فقط في كل نافذة
- مقاييس: الدقة المتوازنة، دقة الشراء/البيع، شارب، أقصى تراجع، نسبة الصفقات الرابحة،
  مقارنة بالشراء والاحتفاظ — بعد خصم تكلفة تداول 0.4%
- النتائج مجمّعة عبر حتى 12 سهماً لإحصائيات أكثر موثوقية من سهم واحد

## التشغيل محلياً

### 1) توليد البيانات والنماذج
```bash
cd backend
pip install -r requirements.txt
python train_model.py     # يدرّب النموذجين (يحتاج إنترنت)
python snapshot.py        # ينشئ snapshot.json
```

### 2) الواجهة
```bash
cd frontend
npm install
npm run dev               # http://localhost:5173
```
الواجهة تقرأ `public/snapshot.json` تلقائياً. لتشغيل باك-إند حيّ اختياري:
```bash
cd backend && python main.py        # http://localhost:8000
# ثم في frontend/.env ضع VITE_API_URL=http://localhost:8000
```

## النشر (مجاناً)

1. **GitHub Actions**: فعّل الـ workflow (يعمل يومياً + يدوياً عبر *Run workflow*).
   - (اختياري) أضف سرّاً باسم `FIREBASE_SERVICE_ACCOUNT` بمحتوى ملف الخدمة لمزامنة
     التوصيات إلى Firestore.
   - ⚠️ **لا تدفع كوداً (`git push`) بينما الـ Action يعمل** — الـ Action يعمل
     commit تلقائياً لتحديث البيانات في نهايته، وأي دفع متزامن يسبب تعارض
     "fast-forward" يُفقِد عمل الـ Action بالكامل (الـ runner مؤقت ويُحذف عند الفشل).
2. **Vercel**: اربط المستودع — **Root Directory يجب أن يكون `frontend`** (وليس
   `backend` — الإعداد التلقائي قد يقترحه خطأً). الإعداد جاهز في `frontend/vercel.json`.
   - حساب GitHub الذي يعمل منه `git commit` يجب أن يملك صلاحية على المستودع (إن كان
     خاصاً) وإلا سيُحظر النشر التلقائي على خطة Vercel المجانية برسالة
     "commit author did not have contributing access".
   - أو `firebase deploy --only hosting` (الإعداد جاهز في `firebase.json`).

## نقاط الـ API (للباك-إند الاختياري)
